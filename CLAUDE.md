## Жёсткие правила (нарушение = переделка)

### 1. Git — коммиты можно, push и история — нет
**Изменено 25.08.2026 решением автора.** Раньше запрещались любые git-команды;
теперь разрешены локальные коммиты, потому что работа идёт длинными
автономными сессиями и терять её между блоками нельзя.

Разрешено выполнять: `git add`, `git commit`, `git status`, `git diff`, `git log`.

Запрещено выполнять всегда: `git push`, `git pull`, `git merge`, `git rebase`,
`git reset --hard`, `git tag`, `git init`, любые команды `gh`, меняющие состояние,
и любые операции, переписывающие уже существующую историю.
Push делает автор сам, из терминала, когда посмотрит diff.

Причина, по которой остальное запрещено: у проекта один автор, и удалённая
история — доказательство авторства. Ассистент её не трогает.

**Ноль следов ассистента — это неизменно.** В сообщениях коммитов, в описаниях PR,
в тегах и в CHANGELOG запрещены: `Co-Authored-By:` в любом виде,
`Generated with Claude Code`, `🤖 Generated with ...`, упоминания моделей
(Claude, Opus, Sonnet, Haiku, GPT) и ссылки на claude.com / anthropic.com.
Сообщение коммита пишется так, как его написал бы автор: по-русски, по существу,
в формате `stage2: краткое описание` (префикс — по номеру текущего этапа).

Перед коммитом — `git status`, чтобы случайно не утянуть `.env`, базу, мусор из
корня (`https:/`) или чужие файлы. Не использовать `git add .` — перечислять файлы.

### 3. Объём работы
Один блок из `PLAN.md` за раз. Не забегать вперёд, не рефакторить соседние
блоки «заодно». Проблему в другом блоке — записать в отчёт, не чинить сразу.

### 4. Зависимости
Только то, что уже в `requirements.txt`. Новая библиотека — сначала спросить и обосновать.

### 5. Язык
Комментарии, docstring, тексты бота, сообщения об ошибках — русский.

### 6. Код для людей
Явные имена, без магии, без метаклассов и динамических импортов. В шапке каждого
модуля `core/` — 3–5 строк: зачем модуль, что осознанно не делает, на что опирается.

### 7. Честность
Не писать «готово», не проверив. Не глушить ошибки try/except ради зелёного прогона.
Не выдумывать содержимое файлов — открывать и читать.

### 8. Секреты
Реальные ключи и токены — только в `.env` (в `.gitignore`). В репозиторий — только
`.env.example` с пустыми значениями. Не выводить содержимое `.env` в чат.

## Формат сдачи блока
Закончив блок, выдать ровно три вещи:
1. список созданных/изменённых файлов — по строке, что там;
2. что проверить руками — конкретные команды и ожидаемый результат;
3. **коммит блока — ассистент делает его сам**, перечисляя файлы явно:
   `git add <файлы> && git commit -m "stage2: описание"`. Push не делает
   никогда — это автор, из терминала, посмотрев `git log` и `git diff`.

**Останавливаться ли после блока — зависит от режима:**
- *интерактивный* (автор за клавиатурой) — остановиться и ждать;
- *автономный* (длинный запуск по всему плану) — закоммитить и идти
  к следующему блоку, не спрашивая. Останавливаться только на том, что план
  прямо помечает как требующее решения автора.
