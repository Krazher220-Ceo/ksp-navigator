# tests/ — как здесь всё разложено

До 04.09.2026 все 69 файлов лежали одной плоской кучей в `tests/`.
Найти «где проверяется вход в кабинет» можно было только перебором имён,
а по имени файла не видно, к какому слою он относится: `test_jwt.py`,
`test_queue.py` и `test_pwa.py` выглядят одинаково важными и одинаково
непонятными. Теперь файл лежит в папке того слоя, который он сторожит.

**Правило одно: папка — это слой кода, а не тема.** Тест живёт там, где
живёт то, что он проверяет. Тест, который проверяет сразу несколько
слоёв, идёт в `scenarios/`.

| Папка | Что сторожит | Файлов | Тестов |
|---|---|---:|---:|
| `core/` | модули `core/`: база, LLM-клиент, разбор и сборка КСП/КТП, конспект, очередь, лимиты, транскрипция, талоны входа | 23 | 387 |
| `bot/` | `bot/`: хендлеры, диалоги FSM, навигация, разводка роутера, подтверждение входа | 4 | 285 |
| `web/` | `web/`: FastAPI Mini App и кабинета, все три двери входа (initData, JWT, Telegram) | 18 | 303 |
| `frontend/` | исходники `frontend/` — читаются как текст, браузер не запускается | 8 | 148 |
| `migrations/` | `scripts/migrate_*.py`: идемпотентность и сохранность данных | 10 | 51 |
| `scenarios/` | сквозные пути через несколько слоёв сразу | 4 | 37 |
| `infra/` | живучесть и контракты: бэкап, изоляция базы, SQL-контракт Postgres, ссылки в документации | 5 | 30 |

Итого **1241** тест, около 40 секунд, **без сети**.

## Что лежит рядом с папками

- `conftest.py` — изоляция базы. На время каждого теста `settings`
  указывают на временную SQLite, а не на боевой Supabase. Это свойство
  прогона, а не привычка автора теста: тест, забывший фикстуру, всё
  равно не попадёт в прод. Файл намеренно оставлен в корне `tests/` —
  он должен действовать на все папки сразу.
- `fixtures/` — настоящие файлы для тестов: три `.docx` с разной
  вёрсткой КСП, `.doc` для проверки конвертации, фрагмент записи урока.
  Тоже намеренно один на все папки: дублировать эти файлы по слоям
  значило бы держать четыре копии записи урока.

## Как это устроено технически

Ни в одной папке нет `__init__.py` — и его не надо заводить. Папки
работают как пространства имён (PEP 420), `pytest.ini` с
`pythonpath = .` делает корень проекта видимым, а импорты между
тестами пишутся полным путём: `from tests.web.test_jwt import …`.

Внутри перемещённых файлов корень проекта считается как
`Path(__file__).resolve().parents[2]` — на один уровень дальше, чем было
в плоской раскладке. `fixtures/` — `parents[1] / "fixtures"`. Если
заводите новый файл, копируйте эту строку у соседа по папке, а не у
`conftest.py`: он лежит уровнем выше, и у него `parents[1]` означает
совсем другое.

## Запуск

```bash
pytest                    # весь прогон, 1241 тест, без сети
pytest tests/web          # только кабинет и API
pytest tests/core/test_queue.py -v
pytest -m supabase        # отдельно и осознанно: против настоящей базы
```

Маркер `supabase` (13 тестов, `tests/infra/test_supabase_contract.py`)
`pytest.ini` намеренно держит вне обычного прогона: он требует сети и
боевой базы — ровно того, от чего уходил блок Н0.
