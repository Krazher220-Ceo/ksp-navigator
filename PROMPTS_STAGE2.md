## Как этим пользоваться

1. Вечером: открыть новую сессию Claude Code, поставить **Sonnet 5**,
   вставить `НС-2` целиком. Оставить на ночь.
2. Утром: **переключиться на Opus 5**, вставить `ПА-2`. Он читает, что
   сделано, и пишет отчёт **не трогая код**.
3. Прочитать отчёт ПА-2 самому. Решить, что чинить.
4. Вставить `ПФ-2` — Opus 5 чинит то, что ты одобрил.
5. Посмотреть `git log` и `git diff`, сделать `push` самому.

```

№130) в автономном ночном режиме. За клавиатурой никого нет.

ПЕРЕД НАЧАЛОМ прочитай целиком, не по диагонали:

РЕЖИМ РАБОТЫ — автономный:

СИСТЕМНЫЕ НАСТРОЙКИ Mac (сон на батарее, статический DNS — блок М7.5)

```
Ночью по PLAN_STAGE2.md работала другая модель. Твоя задача — приёмка.
Код НЕ ПРАВИТЬ. Ни одной строки. Только читать и проверять.

Прочитай: CLAUDE.md, PLAN_STAGE2.md, NIGHT_REPORT_STAGE2.md,
затем `git log` за ночь и `git diff` по каждому коммиту.

Проверь по пунктам и напиши отчёт:

1. СООТВЕТСТВИЕ ПЛАНУ. По каждому блоку М1–К6: сделано / сделано
   частично / не сделано. Где отчёт говорит «закрыт», а по коду видно,
   что нет — писать прямо.

2. ГРАНИЦЫ. Двумя отдельными проверками, до всего остального:
   - нет ли в коде хоть чего-нибудь из аналитики покрытия (эмбеддинги,
     косинусная близость, objective_elements, отчёты о покрытии). Не должно

## ПФ-2 — исправление найденного (Opus 5, после ПА-2)

```
Есть отчёт AUDIT_STAGE2.md, автор его прочитал. Чини то, что в нём
отмечено к исправлению.

Правила те же: git add/commit можно, push/pull/merge/rebase/reset --hard/
tag/init и gh — нельзя. Ноль следов ассистента в коммитах. Формат
сообщения: `stage2: краткое описание правки`. Всё по-русски. Новых
зависимостей нет.

Порядок:
- по одному пункту отчёта за раз, от тяжёлого к лёгкому;
- каждая правка — отдельный коммит с перечислением файлов явно;
- после каждой правки — pytest целиком, не только новый тест;
- на каждый исправленный баг — тест, который падал бы ДО правки.
  Проверить это, временно откатив правку, а не поверить на слово.

Чего НЕ делать:
- не рефакторить соседний код «заодно» — только то, что в отчёте;
- не переписывать блоки, которые в отчёте признаны рабочими;
- не глушить проблему try/except, если не понял причину. Не понял —
  напиши в отчёт, что не понял, это честнее.

Закончив — допиши в AUDIT_STAGE2.md раздел «Исправлено»: по строке на
пункт, с номером коммита. Что осталось неисправленным и почему — тоже
списком, без умолчаний.
```
