Перед началом любой работы прочитай целиком **два файла, и только их**:
- `MASTER.md` — мастер-документ, единственный источник правды о продукте
- `PLAN.md` — план текущих работ, по нему идёт работа

самодостаточным: все ограничения и грабли, на которые проект уже наступал,
пересказаны прямо в нём.

`PLAN_STAGE1_EXT.md`, `PLAN_STAGE2.md`, `PLAN_STAGE3.md`, `PLAN_UX.md`,

## Жёсткие правила (нарушение = переделка)

### 1. Git — коммиты можно, push и история — нет
**Изменено 25.08.2026 решением автора.** Раньше запрещались любые git-команды;
теперь разрешены локальные коммиты, потому что работа идёт длинными
автономными сессиями и терять её между блоками нельзя.

Разрешено выполнять: `git add`, `git commit`, `git status`, `git diff`, `git log`.

Запрещено выполнять всегда: `git push`, `git pull`, `git merge`, `git rebase`,
`git reset --hard`, `git tag`, `git init`, любые команды `gh`, меняющие состояние,
и любые операции, переписывающие уже существующую историю.
Push делает автор сам, из терминала, когда посмотрит diff.

Причина, по которой остальное запрещено: у проекта один автор, и удалённая
история — доказательство авторства. Ассистент её не трогает.

**Ноль следов ассистента — это неизменно.** В сообщениях коммитов, в описаниях PR,
в тегах и в CHANGELOG запрещены: `Co-Authored-By:` в любом виде,
`Generated with Codex`, `🤖 Generated with ...`, упоминания моделей
(Codex, Opus, Sonnet, Haiku, GPT) и ссылки на Codex.com / anthropic.com.
Сообщение коммита пишется так, как его написал бы автор: по-русски, по существу,
в формате `stage-ux: краткое описание` (префикс — по текущей группе работ).

Перед коммитом — `git status`, чтобы случайно не утянуть `.env`, базу, мусор из
корня (`https:/`) или чужие файлы. Не использовать `git add .` — перечислять файлы.

### 2. Границы этапа
**Пересмотрено 26.08.2026 решением автора.** Раньше запрещался код этапов 2–7.
Теперь в работе этапы 1 (долг по интерфейсу и живучести) и 2 (аудио,
транскрипция, конспекты) закрыты. Текущие работы — `PLAN.md`.
Этап 3 (аналитика покрытия) отложен автором до сентября 2026.

Конспект урока делается **только из аудиозаписи**: аудио → расшифровка →
транскрипт → конспект → КСП. Генерации конспекта «из темы и учебника, без
записи» в проекте нет — это решение автора, см. `MASTER.md` 0.6, пункт 2.

**Расшифровку делает только xAI STT** — ключ `XAI_API_KEY`, endpoint
`https://api.x.ai/v1/stt`. Решением автора от 29.08.2026 (`MASTER.md` 0.7)
локальный `whisper.cpp` из проекта удалён: он перегревал рабочий MacBook,
разбор — в `C1_REPORT.md`. Ни бинарника, ни модели, ни «локального режима

### 3. Объём работы
Один блок из `PLAN.md` за раз. Не забегать вперёд, не рефакторить соседние
блоки «заодно». Проблему в другом блоке — записать в отчёт, не чинить сразу.

### 4. Зависимости
Только то, что уже в `requirements.txt`. Новая библиотека — сначала спросить и обосновать.

### 5. Язык
Комментарии, docstring, тексты бота, сообщения об ошибках — русский.

### 6. Код для людей
Явные имена, без магии, без метаклассов и динамических импортов. В шапке каждого
модуля `core/` — 3–5 строк: зачем модуль, что осознанно не делает, на что опирается.

### 7. Честность
Не писать «готово», не проверив. Не глушить ошибки try/except ради зелёного прогона.
Не выдумывать содержимое файлов — открывать и читать.

### 8. Секреты
Реальные ключи и токены — только в `.env` (в `.gitignore`). В репозиторий — только
`.env.example` с пустыми значениями. Не выводить содержимое `.env` в чат.

## Формат сдачи блока
Закончив блок, выдать ровно пять вещей:
1. список созданных/изменённых файлов — по строке, что там;
2. **полный** `pytest`, а не только новый тест. На 31.08.2026 эталон —
   594 passed примерно за 30 секунд и без сети. Меньше — что-то сломано;
3. на каждый исправленный баг — тест, который падал бы **до** правки.
   Проверить это временным откатом правки, а не рассуждением, и написать,
   сколько тестов реально упало на откате;
4. что проверить руками — конкретные команды и ожидаемый результат. Если блок
   менял поведение бота, сюда обязательно входит перезапуск
   `launchctl kickstart -k gui/$(id -u)/com.alikhan.kspbot` и проверка в
   Telegram: 27.08 полтора часа бот работал на старом коде;
5. **коммит блока — ассистент делает его сам**, перечисляя файлы явно:
   `git add <файлы> && git commit -m "stage-ux: описание"`. Push не делает
   никогда — это автор, из терминала, посмотрев `git log` и `git diff`.

Отчёт по ходу работы дописывается в `REPORT.md` (создать, если его нет), а не
копится до конца сессии: если сессия оборвётся, автор должен понимать, на чём
остановились.

**Останавливаться ли после блока — зависит от режима:**
- *интерактивный* (автор за клавиатурой) — остановиться и ждать;
- *автономный* (длинный запуск по всему плану) — закоммитить и идти
  к следующему блоку, не спрашивая. Останавливаться только на том, что план
  прямо помечает как требующее решения автора.
