  только если предмет распознан как физика (единственный предмет, для
  которого у нас есть проверенные данные) и совпадает класс; для любого
  другого предмета модели явно говорится оставить поле пустым — учитель
  впишет код сам при `/generate`, тем же путём, что уже работает для КСП
  без автоподстановки.
- **Р4.3, бот-команда `/generate_ktp` — потребовала миграцию схемы, сделал
  её сам, как ты сказал.** `tasks.type` был жёстко ограничен двумя
  значениями. Решение синхронно (как `/upload_ktp`) не подошло по существу,
  не только чтобы обойти миграцию: генерация КТП — это вызов LLM на весь
  учебный год, а не быстрый разбор файла, и это подтвердилось на реальном
  замере (ниже). Синхронно — значит без ретраев, без гарантии уведомления
  при сбое и с шансом потерять прогресс при перезапуске бота; ровно то,
  для защиты от чего существует core/queue.py. Написал
  `scripts/migrate_add_generate_ktp_task_type.py` — SQLite не даёт менять
  CHECK через ALTER TABLE, поэтому пересборка таблицы (CREATE + COPY +
  DROP + RENAME) внутри одной транзакции. Протестировал на синтетических
  базах (сохранность строк, идемпотентность, восстановление индекса) —
  8 тестов, все прошли — и только после этого применил к реальной
  `storage/app.db`.

**Применение миграции к боевой базе — сделано, с бэкапом.** Порядок:
`.backup` во временный файл → `integrity_check` бэкапа → `launchctl
unload` (бот остановлен, чтобы не ловить "database is locked" во время
пересборки таблицы) → миграция → `diff` содержимого tasks до/после (**полностью
совпало**, 2 строки как были) → `integrity_check` реальной базы → пробная
вставка `generate_ktp` с `ROLLBACK` (подтвердила, что CHECK реально
разрешает новый тип) → `launchctl load` → проверка `~/logs/kspbot.out.log`
(`SIGTERM` → `Polling stopped` → `Start polling`, `err.log` пуст). Бот
живой, PID сменился на 15729.

**Реальная проверка живыми вызовами DeepSeek (2 штуки), не только тестами:**
- физика 10А, 68 ч/год: сумма часов сошлась (68/68), 68 записей в
  ktp_entries, ни одного выдуманного кода (проверил явно — список пуст).
  **Первый вызов упёрся в дефолтный httpx-таймаут LLMClient (60с)** и ушёл
  в сетевой ретрай, итоговое время 112с. Нашёл причину: полный КТП на год
  — на порядок больше контента за один ответ, чем один урок КСП.
- **Починил** — `generate_ktp` создаёт свой `LLMClient(request_timeout=180)`,
  не трогая дефолт 60с у КСП-генерации (ей хватает). Перепроверил вторым
  живым вызовом (химия 9А, 34 ч/год): 30.3 сек, без единого ретрая, сумма
  часов сошлась (34/34).
