# ЭТАП 1 — КСП-генератор. Полный план работ

> Рабочий документ исполнителя. Читается вместе с `MASTER.md` (разделы 0, 1.1–1.8).
> Область: **только этап 1**. Всё, что относится к этапам 2–7, в этот план не входит и не делается.
> Версия плана: 1.0 от 24.08.2026.

---

## A. Как пользоваться этим планом

- Работа разбита на **14 блоков (Б0–Б13)**. Блоки идут строго по порядку — каждый следующий опирается на предыдущий.
- Внутри блока — задачи с ID вида `Б3.2`. Каждая задача имеет: **файлы**, **что делает**, **критерий готовности (КГ)**, иногда **ловушки**.
- Задача считается закрытой, только когда выполнен критерий готовности. Не «код написан», а «проверено и работает».
- В конце каждого блока — остановка, отчёт по правилу 0.3 из `MASTER.md`, и команда коммита текстом. Коммит делает автор.
- Один блок = один сеанс работы. Не начинать следующий блок, не закрыв предыдущий.

**Сквозные правила исполнения (нарушение = переделка):**
1. Git-команды не выполняются. Никогда. См. `MASTER.md`, п. 0.1.
2. Никаких библиотек сверх `requirements.txt` без явного согласования.
3. Никакого кода из этапов 2–7: ни whisper, ни OCR, ни Supabase, ни pgvector, ни эмбеддингов, ни Next.js.
4. Все комментарии, docstring, тексты бота и сообщения об ошибках — на русском.
5. Никакой «магии»: явные имена, никаких метаклассов, никаких динамических импортов. Код должен читаться человеком, который придёт после.
6. Каждый модуль в `core/` работает автономно и тестируется без Telegram.

# БЛОК Б2 — LLM-клиент

**Цель блока:** один вызов, который не падает при отказе провайдера и всегда возвращает валидный JSON.

### Б2.1 — `core/llm_client.py`
- **Что:** класс `LLMClient` с единственным публичным методом:
  `async def complete_json(system: str, user: str, schema: dict, max_retries: int = 3) -> dict`
- **Обновлено:** не «primary + fallback» (2 провайдера), а **цепочка провайдеров произвольной длины** из `LLM_PROVIDERS` (`.env`). По умолчанию: `deepseek` (платный, первый) → `gemini` → `grok` → `openai` → `anthropic` (резервные, на бесплатных дневных лимитах) — список расширяемый, добавление провайдера не требует правки кода, только `.env` и (если протокол новый) адаптер в `PROVIDER_KIND`.
- Провайдер без API-ключа в цепочке пропускается молча (не настроен — штатно). Провайдер, у которого запрос провалился после всех своих ретраев (см. ниже) — переход к следующему в списке. Если весь список исчерпан — исключение `LLMUnavailable`.
- Ретраи **только** на `429` и `5xx`, растущая пауза с джиттером (2 попытки → 1 пауза перед второй; при `max_retries=3` — 3 попытки итого у одного провайдера, паузы растут 1с → 2с). На `400`/`401` ретраить бессмысленно — падать сразу, следующий провайдер.
- Всякий вызов логируется: провайдер, модель, число токенов, длительность, исход.
- Три «протокола» ответа (`PROVIDER_KIND`): `openai_compatible` (deepseek, grok, openai — общий REST-формат), `gemini` (свой формат запроса/ответа, ключ в query-параметре), `anthropic` (свои заголовки и формат). Новый OpenAI-совместимый провайдер добавляется без нового адаптера.

### Б2.2 — Гарантия валидного JSON
- **Что:** ответ модели чистится от markdown-обёртки (```json … ```), парсится. Если `json.loads` упал — **один** повторный запрос **тому же провайдеру** с добавкой «предыдущий ответ не распарсился, верни строго JSON». Если и он упал — `LLMBadResponse`.
- **Ловушка:** не парсить регулярками. Не «чинить» кавычки вручную. Один повтор, потом честная ошибка.
- **КГ:** `pytest tests/test_llm_client.py` с замоканным httpx (реальные вызовы к провайдерам запрещены): (а) успех первого провайдера в цепочке; (б) первый провайдер отдаёт 500 → успех второго; (в) все провайдеры в цепочке легли → `LLMUnavailable`; (г) кривой JSON → один повтор тому же провайдеру → успех; (д) 429 → ровно 3 попытки с растущей паузой перед переходом к следующему провайдеру.

**Отчёт блока Б2 → коммит `stage1: LLM-клиент с фоллбэком и ретраями`**

# БЛОК Б3 — Парсер КСП и профиль стиля

**Цель блока:** из 2–5 реальных файлов учителя получить JSON-профиль его манеры.

### Б3.1 — Конвертация `.doc` → `.docx`
- **Файлы:** `core/ksp_parser.py`
- **Что:** функция `ensure_docx(path) -> Path`. Если на входе `.docx` — вернуть как есть. Если `.doc` — вызвать `soffice --headless --convert-to docx --outdir <tmp>`, таймаут 60 сек. Если LibreOffice не установлен — понятная ошибка на русском с инструкцией.
- **КГ:** на реальном `.doc` файле возвращается читаемый `.docx`.

### Б3.2 — Извлечение структуры документа
- **Что:** `parse_ksp(path) -> dict`. Через `python-docx` вытащить: заголовки, все таблицы (список строк-ячеек), абзацы вне таблиц. Нормализовать: убрать пустые ячейки, схлопнуть пробелы, привести регистр заголовков.
- **Ловушка:** реальные КСП учителей свёрстаны по-разному — таблица может быть одна на весь документ, а может быть пять. Не рассчитывать на фиксированный индекс таблицы; искать по содержимому ячеек-заголовков («Этап урока», «Действия педагога» и т. п.), с учётом опечаток и разного регистра.
- **КГ:** на 3 разных по вёрстке файлах-фикстурах возвращается непустая структура, ни один не роняет парсер.

### Б3.3 — Построение профиля стиля
- **Что:** `build_style_profile(parsed_list: list[dict]) -> dict` — собирает из 2–5 разобранных КСП один профиль. Через LLM (`complete_json`) заполняются четыре поля, ровно как в таблице `style_profiles`:
  - `goal_phrasing` — 3–5 характерных формулировок целей урока, дословно
  - `stage_structure` — типичные этапы с таймингом, в порядке следования
  - `assessment_methods` — методы оценивания, которые встречаются чаще одного раза
  - `resources_used` — ресурсы, которые учитель обычно указывает
- **Ловушка:** профиль строится **только** из реальных КСП конкретного учителя. Шаблоны из интернета сюда не подмешиваются никогда (`MASTER.md`, п. 1.1.1 и п. 11).
- **КГ:** на фикстурах из 3 файлов получается JSON со всеми четырьмя непустыми полями; `raw_samples_count = 3`.

### Б3.4 — Сохранение профиля
- **Что:** `save_style_profile(teacher_id, profile)` — upsert в `style_profiles` (один профиль на учителя), `updated_at` обновляется.
- **КГ:** повторная загрузка КСП тем же учителем обновляет строку, а не плодит дубли.

**Отчёт блока Б3 → коммит `stage1: парсер КСП и профиль стиля учителя`**

### Б7.1 — `core/queue.py`
- **Что:** `enqueue(type, payload, chat_id) -> task_id`, `claim_next()` (атомарно `pending → processing` одним `UPDATE ... WHERE status='pending'`), `complete(id, result)`, `fail(id, error)`.

- **КГ:** убить процесс во время обработки → после перезапуска задача доделывается, пользователь получает результат.

# БЛОК Б9 — Web API и авторизация

**Цель блока:** API, который нельзя дёрнуть чужому.

### Б9.1 — `web/auth.py` — валидация initData
- **Что:** проверка по алгоритму Telegram:
  1. Разобрать `initData` как query-строку, вынуть `hash`.
  2. Собрать `data_check_string` — остальные пары `ключ=значение`, отсортированные по ключу, через `\n`.
  3. `secret_key = HMAC_SHA256(key="WebAppData", msg=bot_token)`.
  4. Сверить `HMAC_SHA256(key=secret_key, msg=data_check_string)` с `hash` через `hmac.compare_digest`.
  5. Проверить свежесть `auth_date` — не старше 1 часа.
- **Ловушка:** порядок аргументов HMAC на шаге 3 обратный интуиции — именно `"WebAppData"` является ключом, а токен сообщением. Ошибка здесь даёт «всё работает», но проверка не проверяет ничего.
- **Ловушка 2:** без этой валидации API открыт всему интернету — Cloudflare Tunnel даёт публичный HTTPS-адрес. Это отмечено в `MASTER.md` п. 1.8, пункт 9b, как блокирующее.
- **КГ:** `pytest tests/test_auth.py` — валидный initData проходит; изменённый на один символ отклоняется; `auth_date` двухдневной давности отклоняется; отсутствующий `hash` отклоняется.

### Б9.2 — `web/api.py`
- **Что:** FastAPI, зависимость `Depends(verify_init_data)` на **каждом** эндпоинте:
  - `GET /api/templates` → список шаблонов, доступных этому учителю
  - `GET /api/preview/{ksp_id}` → `content_json` для отрисовки таблицы
  - `GET /api/download/{ksp_id}` → отдача `.docx`
  - Отдача статики `web/static/`
- Проверка владения: учитель видит только свои `generated_ksp`. Чужой `ksp_id` → `404`, не `403` (не подтверждаем существование).
- **КГ:** запрос без `initData` → `401`; запрос к чужому КСП → `404`.

# БЛОК Б11 — Инфраструктура: Mac как сервер

**Цель блока:** пока ты в школе, дома всё живо.

### Б11.1 — Cloudflare Tunnel
- **Что:** инструкция и конфиг. **Именованный** туннель (`cloudflared tunnel create ksp`), а не быстрый `--url`.
- **Ловушка:** быстрый режим `cloudflared tunnel --url` выдаёт адрес `*.trycloudflare.com`, который **меняется при каждом перезапуске**. У @BotFather URL Mini App регистрируется один раз — с плавающим адресом всё отвалится после первой же перезагрузки Mac.

### Б11.2 — launchd
- **Файлы:** `launchd/com.alikhan.keepawake.plist`, `launchd/com.alikhan.kspbot.plist`
- **Что:** keepawake по образцу из `MASTER.md` п. 1.4. Агент бота: `KeepAlive true`, `RunAtLoad true`, `StandardOutPath`/`StandardErrorPath` в `~/logs/`, `WorkingDirectory` — корень проекта, python из venv по абсолютному пути.

- **Файлы:** `scripts/watchdog.sh`, `scripts/backup_db.sh`

- **КГ:** в `backup/` появился файл, он открывается `sqlite3` и содержит данные.
