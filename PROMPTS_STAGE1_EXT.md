# Промпты для этапа 1-расширенного

Два шаблона. **НС-1** запускается на ночь на Sonnet 5 и работает автономно.
**ПА-1** запускается утром на Opus 5 и принимает то, что получилось.

Копировать целиком, ничего не дописывая.

---

## НС-1 — ночная автономная работа (Sonnet 5)

```
Работаешь автономно, без человека за клавиатурой. Я ушёл спать.

Прочитай целиком, прежде чем что-то делать:
- CLAUDE.md
- MASTER.md, часть 0 (правила работы) и раздел 1 (этап 1)
- PLAN_STAGE1.md — базовый этап, блоки Б0-Б13 закрыты, для контекста
- PLAN_STAGE1_EXT.md — твой план на ночь, блоки Р1-Р10

Работай по PLAN_STAGE1_EXT.md строго по порядку: Р1, затем Р2, затем Р3
и так далее, сколько успеешь. Не перескакивай, не выбирай "что полегче".
Незакрытый блок ломает следующий.

ПОРЯДОК РАБОТЫ НАД КАЖДЫМ БЛОКОМ

1. Прочитай блок целиком, включая ловушки. Ловушки написаны не для красоты -
   каждая уже ломала этот проект или подобный.
2. Прочитай код, который собираешься менять. Не додумывай его содержимое.
3. Сделай правку.
4. Прогони pytest целиком. Не "pytest tests/test_foo.py" - целиком.
5. Проверь результат по-настоящему, а не только тестом: собери документ и
   прочитай его, вызови функцию и посмотри вывод, прогони сценарий. Тест
   проверяет то, что ты в него заложил; ты можешь заложить не то.
6. Закоммить блок (правила ниже).
7. Иди к следующему блоку.

GIT

Правило изменено 25.08.2026, см. MASTER.md п.0.1. Тебе МОЖНО:
  git add <перечисленные файлы>, git commit, git status, git diff, git log

Тебе ЗАПРЕЩЕНО, всегда, при любой формулировке:
  git push, git pull, git merge, git rebase, git reset --hard, git tag,
  git init, любые gh-команды, меняющие состояние

Push сделаю я сам утром, посмотрев diff.

Коммить после КАЖДОГО закрытого блока, не копи. Один блок = один коммит.
Сообщение коммита - на русском, в формате из плана: "stage1: описание".

Абсолютный запрет, не смягчался и не смягчается: в сообщении коммита не должно
быть ни Co-Authored-By, ни "Generated with", ни упоминаний Claude / Opus /
Sonnet / Anthropic, ни ссылок на claude.com. Коммит должен читаться так, будто
его написал я. Ты инструмент, а не соавтор.

Перед каждым коммитом - git status. В репозитории есть мусор, который не должен
туда попасть: папка "https:/" в корне, .env, storage/app.db, backup/.
Не используй git add . - перечисляй файлы явно.

ЧЕГО НЕ ДЕЛАТЬ

- Не выходить за PLAN_STAGE1_EXT.md. Раздел C этого плана - список запретов,
  прочитай его. Презентации не делать, автор отложил явно.
- Не рефакторить "заодно". Не переименовывать. Не улучшать стиль соседнего
  кода. Только то, что написано в блоке.
- Не добавлять зависимости сверх requirements.txt. Нужна новая - остановись
  и запиши вопрос в отчёт.
- Не менять storage/schema.sql. В базе реальные данные учителя. Если блок
  требует миграции (Р4.3, Р9) - НЕ делай её, запиши вопрос в отчёт и иди
  к следующему блоку. Это прямо оговорено в разделе D плана.
- Не глушить исключения ради зелёного pytest. Упавший тест чинится в коде.
- Не выдумывать содержимое файлов - открывай и читай.
- Не выдумывать коды целей обучения и не переводить форму на казахский
  "на глаз". Нет проверенного источника - остановись, запиши в отчёт.

ЕСЛИ ТЕСТ ПАДАЕТ ПОСЛЕ ТВОЕЙ ПРАВКИ

Разберись, что именно он утверждает. Два разных случая:
- тест фиксирует старое, ошибочное поведение, которое блок как раз и меняет -
  тогда правь тест, но в комментарии напиши, почему старое утверждение было
  неверным;
- тест поймал твою ошибку - чини код, а не тест.
Не путай эти случаи и не решай в свою пользу по умолчанию.

ЕСЛИ ЗАСТРЯЛ

Не топчись на месте больше двух попыток. Запиши в отчёт, что именно не вышло
и что ты пробовал, и иди к следующему блоку. Незаконченный блок честно
помеченный лучше, чем пять часов в одну стену.

ЯЗЫК

Комментарии, docstring, тексты бота, сообщения об ошибках, сообщения
коммитов - русский.

ЧТО ОСТАВИТЬ МНЕ К УТРУ

Файл NIGHT_REPORT.md в корне проекта, на русском:
1. Какие блоки закрыл полностью, какие частично, какие не начинал.
2. По каждому закрытому блоку - одна строка: что изменилось по сути.
3. Что сломалось и как починил.
4. Вопросы, требующие моего решения (миграции схемы, источники данных) -
   отдельным списком, с указанием блока.
5. Итоговый pytest: сколько passed, сколько failed.
6. Что я должен проверить руками - конкретные команды.

Пиши в NIGHT_REPORT.md по ходу работы, после каждого блока, а не в конце.
Если тебя прервут, отчёт должен быть актуальным на момент обрыва.

Начинай с блока Р1.
```

## ПА-1 — утренняя приёмка (Opus 5)

```
Переключаю тебя в режим приёмки. Ночью Sonnet 5 работал автономно по
PLAN_STAGE1_EXT.md, блоки Р1-Р10, без человека за клавиатурой. Он мог
закрыть часть блоков, часть бросить на середине.

Прочитай целиком:
- NIGHT_REPORT.md - что он сам про себя написал
- PLAN_STAGE1_EXT.md - что он был должен сделать
- CLAUDE.md, MASTER.md часть 0
- git log за ночь и полный diff всех ночных коммитов
- код, который он изменил

НА ЭТОМ ШАГЕ НИЧЕГО НЕ ПРАВИШЬ. Только читаешь и составляешь отчёт.

Отчёт NIGHT_REPORT.md - это то, что ассистент думает о своей работе.
Проверяй по коду, а не по отчёту. Расхождение отчёта с реальностью -
это тоже находка, и важная.

ПРОВЕРЬ ПО СПИСКУ

1. СООТВЕТСТВИЕ ПРИКАЗУ (блок Р1 - критичный)
   - порядок колонок "Ход урока" точно как в приложении 4 приказа №130
     в редакции от 30.04.2025 № 98: Этап урока/Время, Действия педагога,
     Действия ученика, Оценивание, Ресурсы. До ночи Ресурсы и Оценивание
     стояли наоборот - проверь, что действительно исправлено И в константе
     билдера, И во всех трёх JSON встроенных шаблонов;
   - формулировки полей шапки дословны;
   - собери документ по каждому из трёх шаблонов и прочитай глазами.
     Не верь тесту на слово.

2. КАЧЕСТВО ГЕНЕРАЦИИ (блоки Р2, Р3)
   - "Действия педагога" - действительно полные реплики, а не удлинённая
     заглушка? Сгенерируй настоящий документ реальным вызовом LLM и прочитай.
   - "Оценивание" - дескрипторы или всё те же "наблюдение"/"опрос"?
   - раздаточные карточки: решения в них правильные? разноуровневость реальная
     или три одинаковые задачи с разными метками?
   - не сломалась ли генерация без карточек (документ по-прежнему законен)?
   - уложилось ли время генерации в KPI < 60 сек, и честно ли это записано
     в KPI_STAGE1.md? Ответ "стало медленнее" - нормальный, замолчанный -
     нет.

3. СТЫКИ БЛОКОВ
   - имена полей совпадают в схеме ответа LLM, в docx_builder, в content_json,
     в предпросмотре Mini App?
   - новые необязательные поля не сломали старые документы?
   - колонка ООП (Р5.3) не выгнала таблицу за поля A4?

4. ГРАНИЦЫ ЭТАПА
   - раздел C в PLAN_STAGE1_EXT.md - список запретов. Проверь импорты и
     requirements.txt: не появились ли tesseract, локальные ML-модели,
     новые зависимости, генерация презентаций.
   - schema.sql не тронут? Если тронут - это нарушение прямого запрета,
     разбираться с этим первым делом: в базе реальные данные.

5. ВЫДУМАННЫЕ ДАННЫЕ
   - коды целей обучения (Р8): выборочно сверь 5 штук. Правдоподобный
     выдуманный код - худшее, что может попасть в документ для завуча.
   - казахские формулировки (Р7): взяты из источника или переведены на глаз?

6. GIT
   - ни в одном ночном коммите нет Co-Authored-By, "Generated with",
     упоминаний моделей или ссылок на anthropic/claude;
   - не утянуто лишнее: .env, storage/app.db, backup/, папка "https:/";
   - один блок - один коммит, а не свалка;
   - ничего не запушено, история не переписана.

7. КАЧЕСТВО
   - заглушенные исключения, пустые except
   - тесты, которые проходят всегда и ничего не проверяют
   - skip без объяснения
   - TODO/FIXME, оставленные в коде
   - обработка ошибок, теряющая исходную причину
   - дублирующаяся логика между старым и новым кодом

ФОРМАТ ОТЧЁТА

Список находок, отсортированный по серьёзности. На каждую:
  - файл и строка
  - что не так, одним предложением
  - конкретный сценарий, при котором это выстрелит
  - критичность: БЛОКЕР / ВАЖНО / МЕЛОЧЬ
  - как чинить, кратко

Отдельным разделом - расхождения между NIGHT_REPORT.md и тем, что в коде.

В конце - одна строка вердикта: можно ли отдавать это учителю.

Git не трогаешь на этом шаге вообще. Ничего не правишь, пока я не скажу.
```

## Как пользоваться

1. Вечером: переключить модель на Sonnet 5, вставить **НС-1**, уйти спать.
2. Утром: прочитать `NIGHT_REPORT.md`, переключить на Opus 5, вставить **ПА-1**.
3. После отчёта Opus — сказать «чини», как в прошлый раз.
4. Push — руками, после того как посмотрел `git log` и `git diff`.
